4. CD WORKFLOW
--------------

File: .github/workflows/cd.yml

The CD workflow starts only after CI succeeds on main, or through a manual
workflow dispatch. It performs:

1. Resolves the exact commit tested by CI.
2. Authenticates to AWS using GitHub repository secrets.
3. Logs in to ECR.
4. Builds the Docker image.
5. Tags the image using the immutable Git commit SHA.
6. Pushes the image to ECR.
7. Copies the current ECS task definition.
8. Replaces the api container image URI.
9. Registers a new task-definition revision.
10. Runs `alembic upgrade head` as a one-off Fargate task.
11. Stops deployment if migration fails.
12. Updates the ECS service.
13. Waits until the ECS service becomes stable.

Required GitHub repository secrets:

- AWS_ACCESS_KEY_ID
- AWS_SECRET_ACCESS_KEY

Never commit access-key CSV files, .env files, API keys, passwords, or secret
values to Git.

6. IMPORTANT ISSUES AND FIXES
-----------------------------

Issue: ECS could not retrieve a JSON key from Secrets Manager.
Cause: The task definition used an incorrect secret ARN/key suffix or requested
a key that did not exist in the selected secret.
Fix: Use the application secret ARN for SECRET_KEY and GOOGLE_API_KEY, and the
RDS-managed master credentials secret for database username/password.

Issue: "unexpected ARN format with parameters".
Cause: The JSON key was appended directly to the random ARN suffix.
Fix: Use the ECS secret valueFrom format:
<secret-arn>:<json-key>::

Issue: ECS task stopped after running migrations.
Cause: A migration task used `alembic upgrade head` as its command. A successful
migration exits normally with exit code 0.
Fix: Treat it as a one-off task, not as the continuously running API service.

Issue: API worked internally but public IP timed out.
Cause: Port 8000 was not reachable through the ECS task security group.
Fix: Verify public IP assignment, subnet route `0.0.0.0/0 -> Internet Gateway`,
and the security-group inbound rule for TCP port 8000.

Issue: LangSmith warned that ConversationMemoryContext/None had no `.items()`.
Cause: The trace output sanitizer assumed every traced result was a dictionary.
Fix: Make the sanitizer accept mappings, objects, and None, and return a safe
mapping for LangSmith.

Issue: GitHub CD failed at DescribeTaskDefinition with AccessDeniedException.
Cause: The enterprise-ai-deployer IAM user had ECR permissions but lacked ECS
deployment permissions.
Fix: Add scoped permissions for DescribeTaskDefinition, RegisterTaskDefinition,
DescribeServices, UpdateService, RunTask, DescribeTasks, and iam:PassRole.

9. ECS INTERVIEW QUESTIONS AND SHORT ANSWERS
--------------------------------------------

Q1. What is Amazon ECS?
A. ECS is AWS's managed container orchestration service. It schedules and
manages containers using either Fargate or EC2 capacity.

Q2. What is the difference between ECS and EKS?
A. ECS uses AWS-native container orchestration. EKS provides managed
Kubernetes. ECS is generally simpler; EKS is useful when Kubernetes APIs and
ecosystem portability are required.

Q3. What is an ECS cluster?
A. It is a logical grouping of services, tasks, and compute capacity.

Q4. What is an ECS task definition?
A. It is a versioned blueprint describing containers, images, CPU, memory,
ports, environment variables, secrets, roles, logging, and health checks.

Q5. What is an ECS task?
A. A task is a running or stopped instance of a task definition.

Q6. What is an ECS service?
A. A service maintains the desired number of long-running tasks and performs
deployments, replacement, health monitoring, and load-balancer integration.

Q7. What is the difference between Fargate and ECS on EC2?
A. With Fargate, AWS manages the underlying compute. With EC2 launch type, the
team manages EC2 instances, capacity, scaling, and patching.

Q8. What is the difference between task role and task execution role?
A. The execution role is used by the ECS agent to pull images, retrieve secrets,
and write logs. The task role is used by application code inside the container
to call AWS APIs.

Q9. How does ECS pull a private ECR image?
A. The ECS agent uses the task execution role to obtain ECR authorization and
download image layers.

Q10. How are secrets supplied to containers?
A. The task definition references Secrets Manager or SSM Parameter Store. ECS
retrieves values using the execution role and injects them at task startup.

Q11. Why use an immutable image tag such as the Git SHA?
A. It identifies the exact source revision, prevents ambiguity from mutable
tags, and makes rollback and auditing easier.

Q12. What happens during an ECS rolling deployment?
A. ECS starts tasks using the new task definition, waits for them to become
healthy, and then drains/stops old tasks according to minimum and maximum
healthy-percent settings.

Q13. What is the ECS deployment circuit breaker?
A. It detects a deployment that cannot reach a steady state, marks it failed,
and can automatically roll back to the last successful deployment.

Q14. Container health check versus ALB health check?
A. A container health check runs inside the task. An ALB health check tests
whether the target is reachable and serving requests through the network path.

Q15. How would you debug a stopped ECS task?
A. Inspect stoppedReason, container reason and exit code, service events,
CloudWatch logs, task-definition image/secrets, IAM permissions, health checks,
security groups, routes, and available CPU/memory.

Q16. Why can an ECS task have a public IP but still be unreachable?
A. Its security group, NACL, route table, application bind address, or listening
port may block traffic. The application must normally bind to 0.0.0.0.

Q17. How should ECS connect securely to RDS?
A. Keep both in the same VPC, preferably use private subnets, allow PostgreSQL
only from the ECS security group, encrypt connections, and store credentials in
Secrets Manager.

Q18. How should database migrations be handled in CD?
A. Run migrations as a separate one-off task, wait for exit code 0, and deploy
the application only after migration succeeds. Migrations should be backward
compatible for zero-downtime deployment.

Q19. How do you roll back an ECS deployment?
A. Update the service to a previous task-definition revision or let the circuit
breaker roll back automatically. Immutable image tags make this reliable.

Q20. Why use an ALB instead of a task public IP?
A. Task IPs are ephemeral. An ALB provides a stable endpoint, health checks,
TLS termination, routing, scaling support, and controlled security groups.

Q21. How does GitHub Actions deploy to ECS?
A. CI tests the commit. CD authenticates to AWS, builds and pushes an image,
registers a task-definition revision, runs migrations, updates the service, and
waits for stability.

Q22. Why is iam:PassRole required during deployment?
A. The deployment principal must be allowed to pass the task execution/task
roles referenced by the new task definition to ECS tasks.

Q23. What should be monitored in production?
A. Running versus desired tasks, deployment failures, CPU/memory, ALB target
health, HTTP error and latency rates, application exceptions, RDS metrics, and
CloudWatch log alarms.

Q24. How would you improve this deployment for production?
A. Use private tasks behind an HTTPS ALB, GitHub OIDC, least-privilege IAM,
autoscaling, alarms, backups, secret rotation, vulnerability scanning, smoke
tests, and automatic rollback.
